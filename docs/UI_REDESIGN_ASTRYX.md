# Agent Workbench UI 重设计：Astryx 适配方案

> 状态：设计提案，待用户确认方向后再建正式 GUI 工程
> 日期：2026-11-13
> 分支：`design/ui-redesign-astrxy`（从 `main` 切出，本地留存，未推送）
> 范围：只做设计说明与静态 mockup；**未修改 `src/`，未修改 `spike/electron`**
> 设计稿位置：`design/ui-redesign-astrxy/mockups/`
> 品牌来源：`design/brand-icon` @ `62957d8` 上的 `docs/DESIGN_SYSTEM.md`、`docs/BRAND_GUIDELINES.md` 与 `assets/branding/`

---

## 1. 结论先行

1. **Astryx 适合作为组件层，不适合作为品牌层。** 采用 Astryx 的 AppShell、Section、Table、Badge、StatusDot、Field、Banner 等组件结构与交互约定；颜色、字体、图标、圆角、间距仍以现有品牌规范为准。
2. **不做“深色开发者仪表盘”。** 默认浅色（Paper），深色模式作为可选主题；不使用紫蓝渐变、辉光、玻璃拟态、统计图表或 emoji。
3. **信息架构改为任务控制台，而不是卡片堆叠。** 左侧导航 + 任务列表/详情主区 + 紧凑状态栏；引擎与执行器状态放到顶栏、右栏和设置页，不单独做“仪表盘”。
4. **任务详情是全屏日志控制台。** 日志按“时间 / 流类型 / 内容”结构化显示，支持筛选、搜索、自动滚动、复制与跟进消息；不使用原始 JSON 直接铺屏。
5. **正式工程建议：Vite + React 19 + TypeScript + Astryx 预编译 CSS + 自定义静态主题。** 不采用运行时主题注入，避免与 Electron 严格 CSP 冲突；用适配层隔离 Astryx Beta 的 API 变化。
6. **当前只完成设计提案与 5 个静态高保真稿。** 正式 GUI 工程、日志虚拟列表、IPC 接入、CSP 回归、打包验证都留到方向确认之后。

## 2. 设计目标与边界

### 2.1 目标

- 让用户打开应用后 3 秒内知道：引擎是否在跑、有哪些任务、哪个任务需要关注。
- 让“派发任务 → 看日志 → 跟进/取消”形成一条连续路径，不来回找入口。
- 在 1440×900 的窗口内保持高信息密度：任务表、日志、状态同屏可见。
- 用现有品牌建立识别：Ink / Paper / Signal Orange、Converge 图标、系统字体。
- 用 Astryx 的组件契约减少自造控件，保证密度、焦点、状态与可访问性基线。

### 2.2 边界

- 只覆盖 `docs/MVP_SCOPE.md` 的 v0.1：任务列表、任务详情 + 实时日志、派发、取消、执行器状态、引擎管理、设置、自动更新、关于页。
- 不做多项目、历史统计仪表盘、定时任务、云同步、插件、macOS。
- 不改变 `src/` 的 MCP 引擎行为；正式 GUI 通过既有 IPC/MCP 接口接入。
- 不重画品牌图标或字标；只使用 `assets/branding/` 中已批准的 SVG。
- 本轮不建正式 GUI 工程，不推送远程分支。

## 3. 对 spike 原型的具体批评

先看 `spike/electron` 的界面（源码在 `spike/electron` 分支，截图见其 `artifacts/`）。它证明了 Electron 与引擎链路可行，但界面更像“调试面板”，不是“任务控制台”。以下问题按品牌禁用项与信息架构逐条对照。

### 3.1 配色：直接违反品牌底色与强调色约束

spike 的 `renderer/styles.css` 使用：

```css
--bg: #0f172a;
--card: #16213c;
--card-2: #1c2a4a;
--accent: #4f8cff;
```

问题：

- 深海军蓝底 + 电光蓝强调，是典型的“AI 开发者工具”默认审美，与品牌的 Paper `#F5F3EE` / Ink `#1E2126` 无关。
- Signal Orange `#E85D26` 完全没有出现；品牌唯一的强调色被蓝色替代。
- 蓝底白字、蓝色按钮、蓝色徽章形成大面积冷色，违反“90% 中性色 + ≤10% 橙色”的比例约束。
- 只有深色模式，没有品牌浅色主界面；在白天的桌面工作流里显得沉重。

**新方案：** Paper 为页面底，白色为表面，Ink 为正文，Signal Orange 只用于主操作、选中、运行中与焦点；深色模式保留品牌 token，不引入蓝色。

### 3.2 布局：五张卡片堆叠，没有任务主线

spike 的 `renderer/index.html` 是纵向五张卡片：

1. 引擎控制；
2. 任务与日志左右分栏；
3. `ELECTRON_RUN_AS_NODE` 验证；
4. 自动更新；
5. 关于。

问题：

- 没有导航层级，所有内容同权；用户无法判断“现在该看任务还是看引擎”。
- `ELECTRON_RUN_AS_NODE` 这种工程验证信息被提升为一级界面内容，属于把调试信息暴露给最终用户。
- 任务列表和日志被塞进同一张卡片，日志空间不足；任务详情、派发、设置没有独立入口。
- 每张卡片都是圆角容器，形成“卡片套卡片”的视觉噪音；品牌要求的是清晰的工作台，不是卡片展览。

**新方案：** AppShell（顶栏 + 左侧导航 + 主内容），任务列表/详情/派发/设置/关于各自成为页面；工程验证信息移出主界面，只在关于页或诊断信息中出现。

### 3.3 字体与排版：字号、字重、大小写都不在品牌尺度上

spike 中：

```css
.badge { border-radius: 999px; }
th, td { font-size: 12.5px; }
.grid dt {
  text-transform: uppercase;
  letter-spacing: 0.04em;
  font-size: 11px;
}
button { border-radius: 7px; }
.card { border-radius: 10px; }
```

问题：

- 12.5px 表格字号不在品牌字号表（11/12/13/14/16/20/24/32）里，阅读密度高但稳定性差。
- 11px 全大写 + 字距的英文标签，是典型的“仪表盘装饰”，品牌明确禁止无意义全大写长英文。
- 7px、10px 圆角是随手值；品牌只允许 2/4/8/12。
- 胶囊徽章（999px）直接违反“禁止胶囊”约束。
- 缺少稳定的字号层级：标题、正文、辅助信息之间差异不足。

**新方案：** 14px 正文 / 13px 标签 / 12px 小字 / 11px 注释；代码 13px Cascadia Code；圆角只用 4/8/12；徽章 20px 高、4px 圆角、12px/600。

### 3.4 状态与数据：把内部枚举直接丢给用户

spike 的 `renderer.js` 直接渲染：

- 原始 ISO 时间戳；
- `WORKING` / `COMPLETED` 等内部枚举；
- 任务 UUID 截断到 8 位；
- 原始 JSON 日志行；
- `uptime ...s` 这样的秒数。

问题：

- 用户需要自己把 `WORKING` 翻译成“运行中”，把 ISO 时间换算成“刚刚”。
- 原始 JSON 日志在视觉上不可扫读，错误行和普通输出没有层级。
- 任务 ID 截断后既不是完整 ID，也不是可读编号；复制和排查都困难。
- 没有“颜色 + 文本 + 圆点”的状态系统，状态靠颜色或裸文字，违反品牌的可访问性要求。

**新方案：** 状态统一为圆点 + 文本（运行中/成功/失败/已取消/排队中）；时间显示相对时间 + 绝对时间；任务使用短编号 `#T-1042` 与原始 ID 并存；日志按系统/输出/警告/错误分列，保留行号与毫秒时间。

### 3.5 操作与状态：没有派发、设置、空态、错误态、确认

spike 缺少：

- 派发新任务界面；
- 设置界面（token、端口、代理）；
- 取消任务的二次确认；
- 空列表、加载中、引擎不可用、执行器不可用、日志为空等状态；
- 明确的“一个区域一个主操作”。

结果是界面只能“看”，不能完成 MVP 的核心闭环。

**新方案：** 任务列表与派发页各有且只有一个主操作；取消任务使用 AlertDialog；设置页有保存栏与脏状态；列表、日志、派发都补齐空态/错误态/禁用态。

### 3.6 品牌资产：图标与字标只是“放上去”，没有形成系统

- spike 顶栏用了 `logo-inverse.svg`，但整体是蓝色开发者面板，品牌图标像贴纸。
- 没有图标系统；按钮靠文字，状态靠颜色。
- 没有使用品牌规定的 16px 线性图标语言，也没有统一的 32px 控件高度。

**新方案：** 顶栏使用批准的 lockup；关于页使用完整 lockup（不手工排字标）；导航与按钮统一 16px 线性图标；图标只做辅助，不替代文本。

## 4. Astryx 选型评估

### 4.1 调研口径

- 当前网络环境无法直接打开 `github.com/meta/astryx` 与 `astryx.atmeta.com`（域名校验/连接被重置），因此本轮以 npm registry 上的实际包为准：
  - `@astryxdesign/core@0.7.15`（MIT）
  - `@astryxdesign/theme-neutral@0.7.15`（MIT）
  - `@astryxdesign/build`、`@astryxdesign/cli`
- 读取了包内 `README`、`package.json`、`dist/index.d.ts`、组件 `.doc.mjs`、`theme.css`、`neutralTheme.ts`，并用 CLI 的 `docs tokens/*` 核对 token。
- 公开介绍称 Astryx 有 150+ 组件；本次在 `0.7.15` 的 `dist/index.d.ts` 中实际数到 **105 个组件导出模块**。差异来自统计口径（是否把 hooks、工具、图标、主题组件算作“组件”），正式选型以锁定版本的导出为准。

### 4.2 技术匹配

| 项目 | 结论 |
|---|---|
| React 版本 | Astryx 要求 React 19+；正式 GUI 使用 React 19，匹配 |
| 样式方案 | Astryx 基于 StyleX，peer 依赖 `@stylexjs/stylex ^0.19.0` |
| Electron 兼容 | Electron 44.4.5 内置 Chromium 152；Astryx Tier 1 要求 Chrome/Edge 125+，满足 |
| 浏览器能力 | 使用 Popover API、CSS anchor positioning、`light-dark()`；Chromium 152 支持 |
| CSS 引入 | 预编译 CSS 顺序：`reset.css` → `astryx.css` → 主题 `theme.css` |
| 主题 | `Theme` provider + `defineTheme({ extends: neutralTheme, tokens, ... })`；可用 `theme build` 生成静态 CSS |
| 组件覆盖 | AppShell、TopNav、SideNav、Layout、Section、Card、Table、Badge、Button、IconButton、Selector、Field、TextInput、TextArea、ProgressBar、EmptyState、Toast、Banner、AlertDialog、Dialog、StatusDot、Timestamp、MetadataList、CodeBlock、List、Item、SegmentedControl、TabList 等 |
| 缺口 | 没有现成的日志查看器/虚拟列表；任务日志需要按 Astryx token 自定义 |
| 许可 | MIT，可用于本地桌面应用；仍需在关于页保留第三方许可说明 |

### 4.3 建议的工程形态

```
Electron renderer
  ├─ React 19 + TypeScript
  ├─ Vite（本地构建，无 SSR）
  ├─ Astryx 预编译 CSS（reset → astryx → theme）
  ├─ agent-workbench 静态主题（theme build 产物）
  ├─ 适配层 src/ui/astryx/*（隔离 Beta API）
  └─ 应用样式（CSS variables + 少量布局 CSS）
```

原则：

- **不直接把 Astryx 默认主题当产品主题。** 默认蓝色强调、Figtree 字体、胶囊 Badge 都必须覆盖。
- **不在运行时注入主题。** Astryx 运行时主题注入使用 `useInsertionEffect`，与严格 CSP 的兼容性需要额外验证；v0.1 用 `theme build` 产出静态 CSS，CSP 更可控。
- **不把 Astryx 组件散落到每个页面。** 用适配层封装 Button、Badge、Status、Table、Field 等，页面只依赖应用层组件；Astryx 升级时改一处。
- **版本锁定。** `package.json` 精确版本 + lockfile；不在 v0.1 使用 `^0.7.x` 浮动升级。
- **无外部字体/CDN。** 继续使用系统 Segoe UI Variable Text / Microsoft YaHei UI 与 Cascadia Code，避免离线环境字体缺失。

### 4.4 Astryx Beta 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Beta / 0.x API 变动 | 组件 props、主题 token 可能改名 | 锁定 0.7.15；适配层封装；升级前跑视觉回归与类型检查 |
| 运行时主题注入与 CSP 冲突 | 严格 CSP 下样式可能被拦截 | 使用静态主题 CSS；不调用运行时主题注入；CSP 回归测试 |
| 组件内联 `style` 属性 | `style-src` 严格时可能被拦截 | 逐一审计 Popover/Dialog/Progress 等组件；必要时只对 `style-src-attr` 开受控例外，或替换组件 |
| 默认视觉与品牌冲突 | 蓝色强调、Figtree、胶囊 Badge、白字橙底 | 主题 token 覆盖 + 组件级覆盖 + 截图对比 |
| 文档与包版本不一致 | 按文档写出的 props 在实际版本不存在 | 以锁定包内 `.d.ts` / `.doc.mjs` 为准；升级时重新核对 |
| 组件覆盖不足 | 日志查看器、虚拟列表、复杂键盘交互 | 日志流自定义；表格先用 Astryx Table，数据量大时加窗口化 |
| 可访问性回归 | Beta 组件的焦点/ARIA 可能不完整 | 键盘走查、焦点可见、StatusDot 必须带文本、Dialog 焦点陷阱测试 |
| 包体积/首屏 | 组件与 CSS 增加体积 | 预编译 CSS、按需导入、构建后测量；Electron 本地加载，风险可控 |
| npm/CLI 解析异常 | 当前 CLI 对 0.7.15 的安装解析曾失败 | 固定 registry、lockfile；必要时从已下载 tarball/预编译 CSS 起步 |

**结论：** Astryx 可以作为 v0.1 的组件基础，但必须按“锁定版本 + 适配层 + 品牌主题 + CSP 回归”的方式使用；不能把 Beta 组件直接当成稳定设计系统铺满全应用。

## 5. Token 映射

> 说明：Astryx 仍在 Beta，token 名称可能随版本变化。下表使用本轮在 0.7.15 中核对到的语义名；正式工程以锁定主题包导出的 token 为准。品牌色值来自 `docs/DESIGN_SYSTEM.md`。

### 5.1 颜色

| Astryx 语义 token | 品牌值（浅色 / 深色） | 用途 |
|---|---|---|
| `--color-background-body` | Paper `#F5F3EE` / Ink `#1E2126` | 页面底色 |
| `--color-background-surface` | `#FFFFFF` / `#25292F` | 表格、面板、输入框 |
| `--color-background-card` | `#FFFFFF` / `#25292F` | 离散卡片（少量使用） |
| `--color-background-muted` | `#EDEAE2` / `#2C3138` | 表头、rail、次级区块 |
| `--color-text-primary` | Ink `#1E2126` / Paper `#F5F3EE` | 正文、标题 |
| `--color-text-secondary` | `#5F656E` / `#A8ADB5` | 辅助说明、表头 |
| `--color-text-disabled` | `#8A8F98` / `#8A8F98` | 禁用文本 |
| `--color-border` | `#D8D5CC` / `#3A4048` | 分割线、输入边框 |
| `--color-accent` | Signal Orange `#E85D26` / `#E85D26` | 主操作、选中、运行中、焦点 |
| `--color-on-accent` | Ink `#1E2126` / Ink `#1E2126` | 橙底上的文字/图标 |
| `--color-accent-muted` | `#FBE8DF` / `#3A2620` | 选中行、选中导航、橙色浅底 |
| `--color-text-accent` | `#C0471A` / `#FF8A5C` | 橙色文本、链接、运行中文本 |
| `--color-success` | `#2E7D5B` / `#63C79B` | 成功状态点 |
| `--color-text-success` | `#25684C` / `#63C79B` | 成功文本 |
| `--color-warning` | `#D97706` / `#F0A63C` | 警告状态点 |
| `--color-text-warning` | `#9A5B00` / `#F0A63C` | 警告文本 |
| `--color-error` | `#C0392B` / `#F08A7E` | 失败状态点、危险按钮 |
| `--color-text-error` | `#A93226` / `#F08A7E` | 失败文本 |
| `--color-info` | 中性灰（不引入蓝色） | 信息提示走中性表面 + 文本 |

规则：

- **橙色面积 ≤ 10%。** 只出现在主按钮、选中态、运行中状态、焦点环；不做橙色大面积背景。
- **状态必须“圆点 + 文本”。** StatusDot 不能单独使用。
- **信息色不使用 Astryx 默认蓝。** 信息提示使用中性灰表面、Ink 文本；避免蓝色重新进入界面。
- **深色模式不是另一套品牌。** 仍是 Ink/Paper 反转 + Signal Orange，不新增紫色、青色、蓝色。

### 5.2 字体

| Astryx 语义 | 品牌值 |
|---|---|
| 正文字体 | `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif` |
| 代码字体 | `"Cascadia Code", "Cascadia Mono", Consolas, monospace` |
| body | 14 / 22 |
| label | 13 / 20，600 |
| small | 12 / 18 |
| caption | 11 / 16 |
| subtitle | 16 / 24 |
| title | 20 / 28 |
| heading | 24 / 32 |
| display | 32 / 40 |
| mono | 13 / 20 |

- 覆盖 Astryx neutral 主题默认的 Figtree；不加载外部字体。
- 不改变 Astryx 的语义层级，只把各层级的字号/行高/字族映射到品牌尺度。
- 代码/日志、任务 ID、端口、路径使用等宽字体；正文不使用等宽字体。

### 5.3 间距

| Astryx | 值 | 允许使用 |
|---|---:|---|
| `--spacing-1` | 4px | 图标与文本、紧凑内边距 |
| `--spacing-2` | 8px | 控件间距、行内间距 |
| `--spacing-3` | 12px | 卡片内边距、表格单元 |
| `--spacing-4` | 16px | 区块内边距、页面栅格 |
| `--spacing-6` | 24px | 页面区块间距、双栏 gap |
| `--spacing-8` | 32px | 页面左右留白、较大分区 |
| `--spacing-12` | 48px | 极少使用的大分区 |

- 禁用 5/7/9/10/11 等非品牌步进；不要在页面里写 `13px`、`18px`、`22px` 之类的随手间距。
- 表格行高 44px；表头 36px；控件 32px（小号 28px）；顶栏 52px；侧栏 232px。

### 5.4 圆角、阴影、动效、焦点

| 项目 | 品牌映射 |
|---|---|
| `--radius-inner` | 4px：按钮、输入框、Badge、选中导航 |
| `--radius-element` | 8px：面板、Section、rail 卡片 |
| `--radius-container` | 12px：Dialog、AlertDialog |
| `--radius-page` / `--radius-chat` | 覆盖为 12px 或 8px；不保留 28px |
| `--radius-full` | 仅用于状态点、开关滑钮；**不用于按钮/标签/Badge** |
| `--shadow-low` | `0 1px 2px rgba(30,33,38,.08)` |
| `--shadow-med` | `0 4px 12px rgba(30,33,38,.12)` |
| `--shadow-high` | `0 16px 40px rgba(30,33,38,.18)` |
| 动效 | 120ms（hover）/ 160ms（面板）/ 200ms（Dialog）；`cubic-bezier(0.2, 0, 0, 1)` |
| 焦点 | 2px Signal Orange，offset 2px；深色模式用 `--accent-text` |
| 禁止 | 弹性/回弹、辉光、彩色阴影、渐变背景、玻璃模糊 |

### 5.5 组件级覆盖

| 组件 | 覆盖点 |
|---|---|
| Button | 高 32px；圆角 4px；主按钮橙底 + Ink 文字；一个区域只一个 primary；危险操作红色 + 二次确认 |
| Badge | 高 20px；圆角 4px；12px/600；带圆点 + 文本；禁止胶囊 |
| Input / Select / TextArea | 高 32px（TextArea 自适应）；圆角 4px；标签在输入框上方；焦点环 3px 橙色浅环 |
| Table | 表头 36px、行高 44px、12px 表头/13px 单元格；紧凑但不拥挤；选中行橙浅底 + 左侧 2px 橙线 |
| Section / Card | 页面区块用 Section；Card 只用于离散对象；面板圆角 8px、1px 边框，不叠加阴影 |
| StatusDot | 6px 圆点 + 12px/600 文本；颜色 + 文本，禁止纯色状态 |
| Timestamp | 相对时间（刚刚/6 分钟前）+ 绝对时间（14:26:11）；输入 ISO/Unix，输出本地化 |
| ProgressBar | 4px 高、2px 圆角；只用于任务超时进度、更新下载等有确定意义的进度 |
| AlertDialog | 取消任务、停止引擎、清除 token；容器圆角 12px；默认焦点在取消按钮 |
| Toast | 右下/底部；成功/失败用文本 + 图标；不遮挡主操作 |
| EmptyState | 图标 + 一句说明 + 一个主操作；不使用插画、emoji、大面积留白 |
| 日志流 | Astryx 无现成组件；按 token 自定义，13px Cascadia，行号/时间/流类型/消息四列，正式工程用虚拟列表 |

## 7. 逐屏说明

### 7.1 任务列表（`tasks.html`）

**目标：** 一眼看到任务状态与执行器，快速进入详情或派发新任务。

布局：

- 页面头：标题“任务”、统计“6 个任务 · 1 个运行中 · 最后更新 14:32”；右侧“刷新”（secondary）与“派发任务”（唯一 primary）。
- 工具栏：状态分段筛选（全部/运行中/成功/失败/已取消，带数量）、搜索框、执行器筛选。
- 任务表（Astryx Table 风格）：
  - 列：任务（标题 + 短编号 + 原始 ID）、执行器、状态、用时、更新时间、进入详情。
  - 行高 44px；表头 36px；默认按更新时间排序。
  - 选中行橙浅底 + 左侧 2px 橙线；hover 中性表面。
  - 状态：圆点 + 文本（运行中/成功/失败/已取消/排队中）。
  - 时间：相对时间 + 绝对时间（`刚刚` + `14:30:02`）。
  - 用时：`02:14` 等宽数字，不显示无意义的秒级小数。
- 右侧 rail（280px）：
  - 引擎卡：地址、运行时长、启动耗时、健康检查、管理引擎。
  - 执行器卡：claude/dsh 可用性、模型由执行器配置、5 秒刷新说明。
  - 最近失败：一条可点击的失败任务，不做图表。
- 页脚：显示范围 + 自动刷新间隔。

状态设计：

- 空列表：EmptyState（“还没有任务” + 一个“派发任务”按钮）。
- 加载中：表格骨架/加载行，不闪烁。
- 引擎不可用：顶部 Banner + 列表禁用/只读；主操作“派发任务”禁用并说明原因。
- 搜索无结果：保留筛选器，显示“没有匹配的任务” + 清除搜索。
- 任务很多：表格区域滚动，表头 sticky；不做无限卡片。

为什么不是仪表盘：

- 任务控制台的核心是“列表 + 详情 + 操作”；统计图不能帮助用户完成任何一个 MVP 动作。
- 引擎/执行器状态用 rail 的 4 行信息就够，不需要环形图、折线图或大数字卡片。

### 7.2 任务详情 + 实时日志（`task-detail.html`）

**目标：** 在任务运行过程中持续观察、筛选、跟进和取消。

布局：

- 页面头：返回面包屑、任务标题、状态 Badge、执行器/开始时间/已用时；右侧“发送跟进”（secondary）与“取消任务”（danger，二次确认）。
- 警告 Banner：执行器返回未知模型标识时显示，说明“任务继续运行，但模型信息可能不准确”，并提供“查看配置”。
- 日志面板：
  - 工具栏：日志筛选（全部/输出/错误/系统）、搜索、自动滚动开关、复制日志。
  - 日志行四列：行号（001…）、毫秒时间（14:30:02.118）、流类型（系统/输出/警告/错误）、消息。
  - 13px Cascadia Code，20px 行高；错误/警告用语义色 + 文本；代码/路径用 inline code 样式。
  - 正式工程使用虚拟列表，只渲染可视区域；支持跟随底部、暂停自动滚动、复制选中/全部。
- 跟进 composer：多行输入 + 发送（唯一 primary）；`Enter` 发送、`Shift+Enter` 换行；提示“消息会追加到当前任务上下文”。
- 右侧 rail（300px）：
  - 任务信息：短编号、原始 ID、执行器、模型、工作目录、派发时间、超时、最后活动。
  - 超时进度：4px ProgressBar + `2:14 / 30:00`。
  - 执行器：可用状态、PID、心跳、模型、当前任务数。
  - 操作：复制任务 ID、打开数据目录。

状态设计：

- 运行中：日志实时追加；自动滚动开启；取消按钮可用。
- 成功：日志停止；状态变成功；跟进 composer 可禁用或转为“重新派发”；取消按钮隐藏。
- 失败：显示错误 Banner/错误日志；提供“查看错误”“复制日志”“重新派发”。
- 已取消：日志保留；状态中性；不允许跟进。
- 日志为空：EmptyState“任务还没有输出”；保留工具栏。
- 日志加载失败：错误 Banner + 重试，不显示空白面板。

日志解析原则：

- 后端返回结构化字段（时间、流、消息）；前端不把 JSON 直接铺屏。
- 原始 payload 只在“查看原始日志”中展开，默认不显示。
- 过长的行自动换行；保留行号，方便对照执行器输出。

取消任务：

- 点击“取消任务”打开 AlertDialog：标题“取消这个任务？”，说明“正在运行的执行器会被停止，已产生的日志会保留。”，主按钮“取消任务”（danger），次按钮“继续运行”。
- 取消请求进行中：按钮 loading，禁止重复提交；成功 Toast“任务已取消”；失败 Banner 显示原因。

### 7.3 派发新任务（`dispatch.html`）

**目标：** 用最少的字段完成一次可靠派发。

布局：

- 页面头：标题、说明、返回任务列表（secondary）。
- 左侧主区：
  - 执行器：两张 SelectableCard（claude/dsh），显示可用状态、适用场景、默认/备用；不可用时禁用并写原因。
  - 任务内容：Prompt 大文本域（约 220px 高），底部字符计数与“支持 Markdown”；下方说明“以当前工作目录为基准，不自动提交/推送”。
  - 超时：5/15/30/60/120 分钟；默认 30 分钟。
  - 工作目录：只读等宽路径；说明由应用配置决定。
- 右侧 rail（320px）：
  - 派发预览：执行器、超时、工作目录、引擎状态。
  - 唯一 primary“派发任务”。
  - 说明：派发后去任务列表看状态，详情页看日志。
  - 执行器状态卡：claude/dsh 可用性与刷新说明。

状态设计：

- Prompt 为空：主按钮禁用；字段下方提示“请填写任务内容”。
- 执行器不可用：对应卡片禁用；若当前选中项不可用，主按钮禁用并显示 Banner。
- 派发中：按钮 loading，表单只读，防止重复提交。
- 派发成功：Toast“任务已派发”；跳转到任务详情或任务列表（建议跳详情，直接看到日志）。
- 派发失败：Banner 显示引擎/网络/权限错误；保留表单内容，允许重试。
- 超时/工作目录非法：字段级错误，不用全局 Toast。

范围控制：

- v0.1 不加队列优先级、标签、项目选择、模板库；这些不在 MVP 内。
- 工作目录只读，避免用户在 GUI 里误改路径；后续需要多项目时再放开。

### 7.4 设置（`settings.html`）

**目标：** 把 token、引擎、更新、数据目录集中管理，并让危险操作有明确边界。

布局：

- 左侧设置导航（200px）：凭据、引擎、更新、数据。
- 右侧内容区：
  - 凭据：API Token（掩码显示）、safeStorage/DPAPI 说明、“已加密保存”状态、替换、测试连接。
  - 引擎：本地端口、启动方式（GUI 管理/连接现有引擎）、随应用启动、代理、引擎控制（重启/停止）。
  - 更新：自动检查、更新通道、当前版本、检查更新；明确“安装包未签名，SmartScreen 可能提示”。
  - 数据：数据目录（只读）、打开目录、单实例状态。
- 底部 sticky 保存栏：状态“所有更改已保存”/“有未保存的更改”；“还原” + “保存更改”（唯一 primary）。

交互与状态：

- 修改任意字段后，保存栏变为“有未保存的更改”；保存成功 Toast，状态回到“已保存”。
- token 替换使用独立对话框/输入，不在列表里显示明文；测试连接显示成功/失败原因。
- 端口非法（非数字、越界、被占用）时字段级错误；保存前校验。
- 代理提供“跟随系统代理 / 直连 / 自定义”；默认显示当前系统代理，失败时给出可诊断信息（参考 spike 中 `127.0.0.1:7897` 触发 GitHub API 403 的实测）。
- 重启/停止引擎使用 AlertDialog；说明会中断运行中的任务。
- 更新检查中禁用按钮并显示 loading；有更新时显示版本号 + 下载/安装入口；下载中用 ProgressBar；失败显示错误与重试。
- 设置页不提供“清空所有数据”之类的高危操作；v0.1 不做。

### 7.5 关于（`about.html`）

**目标：** 品牌、版本、构建信息、许可与更新的统一入口。

布局：

- 品牌区：批准的 `logo-primary.svg` / `logo-inverse.svg`，不手工排字标；产品定位“AI 编程智能体的任务控制台”；版本 Badge + 更新状态。
- 构建信息：版本、构建日期、平台、Electron、Node、Chromium、更新源。
- 更新：说明自动检查、未签名提示、上次检查时间、检查更新（唯一 primary）。
- 许可与第三方：MIT；Astryx（MIT）、Inter（OFL 1.1）、Lucide（ISC）等。
- 链接：GitHub 仓库、发布记录、Astryx；外链使用 16px external 图标。
- 页脚：版权与“本地优先，任务数据不离开本机”。

原则：

- 关于页不是“关于 + 调试 + 更新 + 许可”四张卡片；用品牌区 + 两栏信息 + 分隔线组织。
- 工程验证信息（`ELECTRON_RUN_AS_NODE`、sqlite）不放在关于页主视觉；需要时放“诊断信息”折叠区或复制诊断按钮。
- 更新失败/无网络时显示原因，不显示假进度。
