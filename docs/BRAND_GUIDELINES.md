## 1. 品牌定位

**一句话：AI 编程智能体的任务控制台。**

Agent Workbench 不是聊天窗口，也不是又一个模型客户端。它把多个编程智能体（Claude Code、DeepSeek Harness 等）的任务接收、调度、执行、日志与状态收拢到一个清晰、可控的工作台上。品牌表达应围绕“任务如何被接住、分配、执行和掌控”，而不是围绕“AI 很聪明”。

---

## 2. 品牌关键词

| 关键词 | 含义 | 视觉/文案落点 |
|---|---|---|
| **编排** | 多执行器、多任务的统一组织 | 汇聚的线条、清晰的任务分组 |
| **调度** | 任务被分配到正确的执行器 | 橙色节点：派发与决策的瞬间 |
| **工作台** | 长期使用、可依赖的操作界面 | 沉稳的墨色底板、克制的界面 |
| **清晰** | 状态、日志、结果一眼可读 | 高对比文字、明确状态词、少装饰 |
| **掌控** | 用户始终知道发生了什么、能做什么 | 可取消、可重试、可查看日志 |

品牌语气：直接、克制、可信。不使用“颠覆”“革命性”“超级智能”等夸张词，不卖弄拟人化人格。

## 3. 图标概念 A「汇聚」

### 3.1 概念

三条路径从不同方向汇聚到一个橙色节点，再由节点继续向右延伸：

- **三条路径**：多个执行器、多个任务来源、多条工作流。
- **橙色节点**：调度与派发的决策点，也是当前被激活的任务。
- **向右延伸的路径**：任务被接住后继续向前执行，而不是停在入口。
- **墨色圆角底板**：工作台台面；提供稳定的深色背景，让纸白线条与信号橙保持高对比。
- **纸白线条与圆头端点**：清晰、可连接、不过度技术化；避免箭头带来的“单向流水线”暗示。

图形不使用机器人、大脑、神经网络、齿轮或仪表盘等俗套符号。

### 3.2 母版

`assets/branding/source/icon-master.svg` 是唯一母版，由用户确认，**不得重绘、改色、改比例或替换线条**。

- 画布：512 × 512
- 底板：`x=24 y=24 w=464 h=464 rx=104`，填充 `#1E2126`
- 线条：`#F5F3EE`，`stroke-width=54`，`stroke-linecap=round`
- 节点：圆心 `(256,256)`，半径 42，填充 `#E85D26`
- 母版 SHA-256（去除末尾换行后）：`6caa545c1fb0839b0c5e3a3cd294e665a43624cbb65b167aec417783ab375caf`
- 已核对：母版内容与用户确认的 SVG 逐字符一致。

无底板的纯图形版本为 `assets/branding/source/mark-only.svg`：几何与母版一致，线条改为墨色 `#1E2126`，节点保持信号橙，供浅色背景与文档使用。**mark-only 不可直接放在深色背景上**（墨色线条会消失）；深色背景使用母版或 `logo-inverse.svg`。

## 5. 图标与字标使用规范

### 5.1 最小尺寸

| 形态 | 最小尺寸 | 说明 |
|---|---|---|
| 应用图标（有底板） | 16 × 16 px | 仅用于 favicon、托盘等；16px 是可辨认下限 |
| 无底板图形 | 24 × 24 px | 小于 24px 时线条与节点开始粘连 |
| 横向字标 | 200 px 宽（数字）/ 24 mm 宽（印刷） | 再小请改用仅图标 |
| 应用图标推荐 | 32 × 32 px 起 | 32px 及以上图形清晰 |

### 5.2 留白

- 横向字标四周留白 ≥ 图标高度的 25%（即 ≥ 48px 于 192px 图标）。
- 仅图标使用时，四周留白 ≥ 图标高度的 12.5%。
- 应用图标本身已含 24/512 的内边距；不要在此基础上再裁切或加白边，平台图标蒙版由系统处理。

### 5.3 背景

| 背景 | 使用 |
|---|---|
| 浅色（Paper `#F5F3EE` / 白） | `logo-primary.svg`、`mark-only.svg`、`icon-master.svg` |
| 深色（Ink `#1E2126` 及更深） | `logo-inverse.svg`、`icon-master.svg` |
| 中性灰/照片 | 使用有底板的 `icon-master.svg` 或字标；确保底板与背景有足够分离 |
| 信号橙底 | 禁止放置图标；橙色节点会与背景融为一体 |

### 5.4 字标

- 横向字标为“图标 + Agent Workbench”的唯一标准组合，文字已转为轮廓路径（Inter Bold，SIL Open Font License），不依赖系统字体。
- 字标文字不得重新用字体排版、改字重、改字距、改大小写或添加副标题。
- 需要单行标题时使用 `logo-primary.svg` / `logo-inverse.svg`，不要手工拼“图标 + 文本”。
- 不提供竖排字标；如需方形场景，使用仅图标。

### 5.5 颜色

- 图标只使用母版中的墨、纸、信号橙三色，不新增颜色。
- 信号橙是“信号”，不是装饰：界面中主要用于主操作、选中、焦点、运行中状态与汇聚节点。
- 中性色应占品牌物料的绝大部分；橙色面积建议不超过 10%。
- 不使用低对比组合（橙 on 橙、纸白 on 纸白、灰 on 灰）。

## 6. 禁用事项

| 禁止 | 原因 | 替代做法 |
|---|---|---|
| **紫蓝渐变** | 与“清晰、掌控”的定位冲突，落入通用 AI 视觉俗套 | 使用墨/纸/信号橙的纯色 |
| **发光（glow/neon）** | 干扰信息层级，降低可读性 | 需要强调时用对比度、留白或 1px 边框 |
| **玻璃拟态（glassmorphism）** | 降低文字对比度，增加视觉噪声 | 实色表面 + 边框 + 克制阴影 |
| **机器人 / 大脑 / 神经网络俗套图形** | 把“AI”当卖点，偏离任务控制台的定位 | 汇聚线条、节点、任务状态等抽象语言 |
| **Emoji 代替图标** | 跨平台渲染不一致，语义不精确，显得不专业 | 16/20/24px 单色线性图标 |
| **无意义仪表盘** | 装饰性图表不帮助用户做决定 | 只展示可操作的状态、进度与日志 |
| 拉伸、压扁、旋转图标 | 破坏几何比例与识别度 | 等比缩放；需要旋转时整体旋转并重新评估 |
| 给图标加描边、投影、渐变、纹理 | 改变母版，降低小尺寸清晰度 | 使用原始 SVG |
| 在图标内添加文字或字母 | 小尺寸不可读，且与字标重复 | 图标与字标分开使用 |
| 把圆角底板改成胶囊/圆形 | 破坏“工作台台面”的识别 | 使用母版固定圆角 104/512 |
| 把 mark-only 放在深色背景 | 墨色线条不可见 | 使用 `logo-inverse.svg` 或母版 |
| 用其他字体重排字标 | 字标是固定资产，不是普通标题 | 直接引用字标 SVG |
| 彩色阴影或多层装饰阴影 | 与克制原则冲突 | 单层中性阴影，或仅用边框 |
| 仅靠颜色表达状态 | 可访问性不合格 | 颜色 + 文字 + 图标 |

### 6.1 常驻 HUD 浮层例外（2026-11-14）

Agent HUD 是常驻在主窗口左侧的状态侧栏，允许使用 `#1E2126` 墨色**胶囊**底座（圆角 28px、1px `rgba(245,243,238,0.10)` 描边、单层中性阴影 `0 8px 24px rgba(30,33,38,0.18)`）与 2px 环形进度。这是对第 5.1 节“不做胶囊化”的唯一例外，仅适用于 HUD 底座，不适用于按钮、输入框、标签或徽标。深色主题下允许将底座提升到 `--surface`（`#25292F`）并把描边提高到 `rgba(245,243,238,0.22)`，避免墨色胶囊与墨色页面背景融为一体；仍不增加发光、渐变或多层阴影。

例外不改变第 6 节的禁用项：

- 仍然禁止发光 / 霓虹、外发光阴影与多层阴影；
- 仍然禁止任何渐变、玻璃拟态与背景模糊；
- 仍然禁止 emoji 作为图标；
- 身份只用单色图形区分（2026-11-14 起 Muse / claude / dsh 使用用户提供的白色标识；此前为 lucide `Cloud` / `Sparkles` / `Terminal`），不用颜色区分 agent；
- 状态必须同时有颜色、图形与文字：进度环颜色 + 状态角标图形 + 悬停卡中的状态文字（空闲 / 干活中 / 等你输入 / 出错）。

HUD 槽位中的 Claude / DeepSeek 等 agent 标识由用户提供，仅用于本机身份识别，**不属于** Agent Workbench 品牌资产，也不在 MIT 许可的授权范围内；公开分发安装包前需重新评估或替换。侧栏的图标只是身份形状，状态一律由本项目的环、角标与文字表达。

## 7. 渲染与验证结果

### 7.1 方法

- 以 `source/icon-master.svg` 为唯一输入，用 sharp（librsvg）以高密度栅格化后，Lanczos3 缩放至 16 / 32 / 48 / 128 / 256 / 512 px。
- 对 16 / 32 / 48px 使用最近邻放大（12× / 8× / 6×），分别在 Paper `#F5F3EE` 与 Ink `#1E2126` 背景上目视检查；512px 以实际尺寸检查。
- 检查项：可辨认性、边缘干净度、透明背景、是否混入文字或多余元素。
- ICO 用 Pillow 由对应 PNG 合成并重新解析校验；ICNS 由 1024px 渲染经 Pillow 生成并重新打开校验。
- 验证日期：2026-11-13。验证人员：本机接管会话。未在 Windows Explorer / macOS Finder / Electron 安装包中做最终视觉确认。

### 7.2 各尺寸结果

| 尺寸 | 可辨认性 | 边缘 | 透明背景 | 多余文字 |
|---|---|---|---|---|
| 512px | 清晰：Y 形三线、圆头端点、橙色节点完整 | 干净，无锯齿/毛边 | 四角 alpha = 0 | 无 |
| 256px | 清晰 | 干净 | 四角 alpha = 0 | 无 |
| 128px | 清晰 | 干净 | 四角 alpha = 0 | 无 |
| 48px | 清晰；节点与线条关系明确 | 干净 | 四角 alpha = 0 | 无 |
| 32px | **可辨认**：三线汇聚与橙色节点清楚，无粘连 | 干净，仅正常抗锯齿过渡 | 四角 alpha = 0 | 无 |
| 16px | **可辨认**：仍能读出 Y 形与橙色节点；属于可辨认下限 | 无杂点；约 1.7px 线宽，右臂与节点略有视觉合并，属正常抗锯齿 | 四角 alpha = 1/255（圆角半径仅 0.75px，抗锯齿导致的近透明像素） | 无 |

结论：

- **16 / 32px 均通过“可辨认”要求**，无多余文字，边缘无异常杂点。
- 16px 是识别下限：不建议在需要精细识别的界面位置使用 16px；favicon/托盘可用，常规界面使用 32px 及以上。
- 圆形底板在 16px 下圆角几乎不可见（0.75px），视觉上接近方形，这是该几何在小尺寸下的正常表现，不通过重绘修正。

### 7.3 容器文件校验

| 文件 | 结果 |
|---|---|
| `agent-workbench.ico` | 17,903 bytes；5 个条目：16 / 32 / 48 / 128 / 256 px，均为 32bpp；Pillow 重新打开成功 |
| `agent-workbench.icns` | 79,523 bytes；包含 `ic07`–`ic14`（128–1024px 及 retina 槽位）；Pillow 重新打开为 1024×1024 RGBA |
| ICNS 限制 | Pillow 生成的 ICNS 未包含 `icp4` / `icp5` 基础槽位；现代 macOS 使用 `ic07` 及以上槽位，但**未在 macOS 真机验证**。正式发布前建议在 macOS 上用 `iconutil` 重新生成并检查 |
| ICO 限制 | 未在 Windows Explorer / 安装包中做大中小图标最终视觉确认；结构校验通过 |

### 7.4 字标验证

- `logo-primary.svg` 在 Paper 背景、`logo-inverse.svg` 在 Ink 背景分别渲染检查：图标与文字对齐、文字轮廓无缺口、无字体替换。
- 字标文字已由 Inter Bold（wght 700，opsz 32）转为轮廓路径，文件不依赖系统字体；Inter 使用 SIL Open Font License。
- 字标渲染检查为 2× 目视检查，未做印刷打样。

### 7.5 mark-only 验证

- 在 Paper `#F5F3EE` 背景上渲染：墨色 Y 形线条与橙色节点清晰可见，无底板。
- 未在深色背景上使用；深色场景使用 `logo-inverse.svg` 或母版。

## 8. 变更与治理

1. `icon-master.svg` 是品牌资产的唯一图形来源；任何尺寸、容器或界面图标都应从它派生。
2. 修改母版、字标或核心色板需单独评审并更新本文件与 `docs/DESIGN_SYSTEM.md`。
3. 概念 B / C 仅作设计记录，不得用于对外物料。
4. Electron 集成（窗口图标、任务栏、安装包、关于页）不在本次范围；集成时直接引用 `assets/branding/app-icon/` 与 `logo/` 下的资产，不复制或重绘。
5. 品牌资产不包含任何第三方商标或未授权字体；字标轮廓来自 OFL 授权的 Inter。
