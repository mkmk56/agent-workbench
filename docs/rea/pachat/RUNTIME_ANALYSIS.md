# Pachat 运行时分析

> 依据：官方文档 /skill.md、/install.md（2026-11-18）。后端内部未公开，见 UNKNOWN_AND_ASSUMPTIONS.md。

## 1. 部署形态

| 层 | 位置 | 说明 |
|---|---|---|
| 中央服务器 | 美国 Railway + Cloudflare | 群聊、路由、唤醒调度、token 管理；消息经过该服务器 |
| Agent 运行时 | 各自主机（本地） | 思考与执行在本地；Pachat 不提供模型、不执行代码 |
| Listener | 各自主机（Node 18+ 单文件 CLI） | 持 SSE 长连接，接事件后本地 spawn Agent CLI |
| 邮件 | Resend | 唤醒失败、@ 未读等通知 |

## 2. Listener 运行时

- **连接**：到 `/events` 的 SSE 长连接；1 分钟连不上服务器则自卸载。
- **会话**：每群一个会话，可续接；每群同时只跑一个任务。
- **上限**：15 分钟无输出即停；1 小时硬上限；每天每群 ≤100 次运行。
- **spawn**：事件到达后在本地 spawn 对应 Agent CLI
  （dsh 走 DeepSeek Harness 应用二进制，应用不必打开）。
- **权限**：群主自己的消息 → 完整权限；别人的消息 → 仅限 Pachat 目录。

## 3. check-in 与 wake 的运行时节律

| 机制 | 节律 |
|---|---|
| check-in | 默认每 10 分钟（可调 2–1440 分钟） |
| wake 节流 | 每 10 分钟 ≤1 次，每天 ≤30 次；群主发帖立即唤醒 |
| wake 失败 | 重试 1 次；连续 3 次失败 → 禁用 + 邮件 |
| @ 未读提醒 | @ 后 10 分钟未读 → 邮件 |
| 消息限流 | 每群每小时 100 条；每条 ≤10,000 字符 |

## 4. 我方运行时的对照

| 维度 | Pachat | 我方 workbench |
|---|---|---|
| Agent 执行位置 | 各自主机 | MOG 本地（Claude/dsh 真实 CLI） |
| 消息存储 | 中央服务器 | 本地 SQLite（data/workbench.db） |
| 唤醒 | check-in + wake + Listener | 尚无（Phase 3） |
| 并发 | 每群同时一任务 | 引擎并发上限 4（dsh 2） |
| 任务上限 | 15 分钟无输出 / 1 小时硬上限 / 100 次/天 | 交换上限 10/线程、回复深度 8、每 epoch 预算 20 |
| 审批 | 无（群主管理） | 审批门（当前关闭）+ 结论卡片 |

## 5. 对 Phase 3 的启示

- Listener 的"一群一会话、可续接、同时一任务"是可直接借鉴的并发模型。
- 15 分钟无输出 / 1 小时硬上限 / 100 次每天是现成的熔断参数起点。
- check-in 间隔可调（2–1440 分钟）值得照搬为配置项。
