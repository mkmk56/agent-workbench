## 1. 核心判断（审查报告的结论，本方案的前提）

1. **改色成本低**：颜色几乎全走 `:root` / `html[data-theme="dark"]` 自定义属性与 Astryx 主题源；硬编码只集中在 5 个文件。改 12 个定义点即可全站去橙，但要复核 170 个触点。
2. **改语义成本高**：`--accent` 目前有四重含义（主操作/选中/焦点、Claude 身份、HUD 工作环、AppStatus 任务运行中）。只换色值 = 四个概念一起变银灰，「主操作」和「正在执行」失去区分度。**必须先拆语义，再定色值**（见 §2）。
3. **层次的根因不是颜色**：磨砂黑目标的 surface 阶梯相邻对比只有 1.02–1.10:1，目标边框 `#292D32` 对 `#101214` 只有 1.35:1。「只换色值」会得到一张没有层次的纯黑平板。**必须用 1px 边框 + 内侧 1px 高光 + 间距与字号层级建立层次**（见 §5）。

---

## 2. 语义拆分（先拆，再换色）

| 原概念 | 新 token | 色值/表现 |
|---|---|---|
| 主操作 / 选中 / 焦点 | `--accent`（保留名，换值） | 冷银灰 `#C5CBD3`；hover `#E0E4E9`；active `#8D97A3`；secondary `#A3ABB5` |
| Claude 身份 | **删除**（决策 A） | 不再有 `--identity-claude`；身份靠 §3 的字形/名称/标签 |
| HUD 工作环（Agent 干活中） | `--hud-working` | 中性亮度动画：墨底上的亮灰弧 + 转速变化，不用颜色表意；状态靠弧的运动与文字 |
| 任务运行中（AppStatus running） | `--status-running` | 中性圆点 + “运行中”文字；不再是橙色徽标 |
| 焦点环 | `--focus-ring` | `rgba(197,203,211,.45)`（冷银灰 alpha），不再是橙色 alpha |

`--identity-muse` / `--identity-dsh` / `--identity-user` 同样删除（12 个 token 全部清理，见审查报告 §2.4）。头像字形标记保留为**形状**而非颜色：Muse “M”、Claude 星号、dsh “d”、用户人形，统一用中性灰底 + 深灰字形。

## 3. 身份表达（决策 A 的落地）

- **头像**：28px 圆形，中性灰底（`--surface-elevated`）+ 深灰字形；不再按 agent 分色。字形本身即身份。
- **名称**：发送者名用正文色加粗（600），不再着色；名称后跟一个小标签（`Muse` / `Claude` / `dsh` / `你`），标签为弱化边框 + 辅助文字。
- **气泡**：所有 agent 消息统一左对齐、无彩色边；用户消息中性深灰底。区分靠头像 + 名称 + 标签 + 布局，不靠颜色。
- **成员行**：头像 + 名称 + 绿点（在线）——绿点是语义色（在线状态），保留但降饱和。
- **长会话扫读**：靠名称 + 标签 + 字形三重冗余；不再依赖颜色扫读。这是 A 方案的代价，用户已接受。

### 4.3 层次解法（审查报告的核心建议，本方案采纳）

色阶本身太扁（1.02–1.10:1），层次不靠色值差，靠三样东西：

1. **1px 低对比边框**：面板与面板之间用 `#292D32` 1px 分隔。
2. **内侧 1px 高光**：面板顶部 `inset 0 1px 0 rgba(255,255,255,.04)`——是内高光，不是外发光，不做 glow。
3. **控件边界**：输入框、按钮、开关等可交互元素的边界用 `#5F666F`（3.23:1，满足 WCAG 1.4.11 的 3:1），让控件在近黑底上“找得到”。
4. **间距与字号层级**：标题 600、正文 400、辅助 400 + 更小字号；消息间距 24px；段落间距靠字号与行高，不靠卡片。

### 4.4 强调色（冷银灰，只用于必要处）

- Primary `#C5CBD3` / Secondary `#A3ABB5` / Hover `#E0E4E9` / Active `#8D97A3`。
- 只用于：主按钮（深灰底 + 浅灰字，或浅灰底 + 深灰字）、选中态、输入焦点、关键操作。禁止全站铺开。
- 主按钮样式：深灰底 `#1D2024` + 浅灰字 `#E0E4E9` + 1px `#383D44` 边；hover 提亮到 `#24282D`；不做纯白按钮（避免“纯黑加纯白”的单调感）。

### 4.5 语义色（去饱和，只做信息传达）

| 状态 | 色值 | 用途 |
|---|---|---|
| 成功 | `#5A9A7A`（低饱和绿） | 完成、对勾 |
| 警告 | `#C99A4B`（柔和琥珀） | 警告、waiting 环 |
| 错误 | `#A85A52`（克制暗红） | 错误、error 环 |
| 信息 | `#6B8CA8`（低饱和冷蓝） | 信息提示 |

### 4.6 浅色「纸白」变体（决策 2）

- 与深色共用同一套 token 名，只换值：纸 `#F5F3EE`、墨 `#1E2126`、边框 `#D8D5CC`、强调色沿用冷银灰系（深灰字 `#5F656E` 作主操作色）。
- 不单独维护两套视觉方案；浅色变体只做 token 值映射，不另写组件样式。

---

## 5. 材质、边框、圆角、阴影

- **材质**：微弱内阴影、极细半透明边框、低对比表面明暗变化、轻微背景模糊（仅浮层与弹窗，backdrop-filter 只用于这两处）、极细腻的金属质感。**不滥用毛玻璃**。
- **边框**：1px 低对比；hover 略微提亮；选中清晰但不刺眼；不用高亮白描边。
- **阴影**：真实、柔和的深色阴影；无彩色投影、无夸张悬浮。
- **圆角**：小控件 5–7px、按钮 7–9px、面板 9–12px、大弹窗 12–16px；不许普遍 20px+。
- **主进程窗口背景**：`main.ts:1047 backgroundColor: '#F5F3EE'` 是硬编码浅色，改磨砂黑后必须同步改为 `#090A0B`，否则启动闪一帧浅米色。

## 6. 聊天界面（核心区域）

- **不做卡片堆叠**：消息内容直接融入工作区，少容器边框，多整体感；消息之间 24px 垂直间距。
- **层次**：用户消息中性深灰底；agent 消息无底色，靠头像 + 名称 + 标签区分；多 agent 同时回复时靠名称行与字形区分。
- **Markdown**：代码块深色底 `#0D0F11` + 1px `#202328` 边 + 复制按钮（右上角，hover 才显）；表格用弱化边框；引用用左侧 2px 中性竖线。
- **附件卡片**：原始文件名 + 类型 + 实际大小 + 解析状态；失败显示原因；历史附件标“历史附件（不可下载）”；不再出现 UUID/0B。
- **Agent 状态**：等待调度 / 思考 / 生成 / 调用工具 / 读附件 / 完成 / 失败——用状态点 + 文字，不做虚假动画；状态点颜色只用中性灰 + 语义色（成功/失败），不用身份色。
- **输入框**：纸夹在左、占位文案“输入消息，@ 提及成员…”、emoji 按钮 + 深灰 pill 发送按钮、橙色焦点边改为冷银灰焦点边、无提示文字。

## 7. 侧边栏与导航

- 深色磨砂背景 `#0B0C0E`；清晰导航层级；选中项低调灰阶高亮（`#1D2024` 底 + 左侧 2px 中性竖线），**不用大面积彩色选中背景**。
- 图标统一简洁线性（lucide，strokeWidth 1.6–2）；hover 自然；无廉价发光。
- 导航轨 96px 保留 Agent HUD 胶囊（用户喜欢）；HUD 工作环改中性亮度动画（见 §2）。
- 侧栏可拖拽/折叠/持久化（重构 P1 任务，不在本方案内，见 REFACTOR_PLAN.md §3.2）。

---

## 8. 动效

- Hover 120–180ms、状态切换 150–220ms、弹窗 180–250ms；ease-out；只动 transform/opacity。
- 禁：无意义循环呼吸、过度弹跳、大缩放、粒子、影响性能的背景动画。
- 注意：手写 CSS 的 `120ms` 死值与 Astryx tempo 刻度（125/225/525–935ms）并存——本方案统一为 token：`--duration-fast: 150ms`、`--duration-normal: 200ms`、`--duration-slow: 250ms`，两处都走 token。
- 照顾 `prefers-reduced-motion`。
